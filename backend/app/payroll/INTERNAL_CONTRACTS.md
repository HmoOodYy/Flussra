# Payroll internal contracts

This guide records cross-module helper contracts verified in the current backend source scan. These names are internal implementation contracts, not an external API. Production callers import the owner directly; tests keep their existing consumer-module monkeypatch seams. This guide and the owner module documentation add no aliases or facade.

## Cross-package internal contracts

| Owner | Supported helper | Consumers | Contract |
|---|---|---|---|
| `app.payroll.workflow_lock` | `acquire_branch_workflow_lock(company_id, branch_id, db)` | Payroll lifecycle/creation/finalization, Payroll Setup locks, Review decisions | Takes PostgreSQL's transaction-level advisory lock keyed by `(company_id, branch_id)` on the caller's active connection transaction. It performs no authorization and does not begin, commit, or roll back the caller's transaction. |
| `app.payroll.guards` | `check_not_in_finalized_period(company_id, branch_id, effective_from, db, *, label=...)` | Compensation assignment approval, Payroll pay-rule creation, Payroll rate approval/auto-approval | Read-only check for the same company and branch and an effective date inclusively within a `Locked` or `Archived` period. Raises HTTP 422 on a match. It owns no authorization, lock, commit, or caller ordering; callers retain their existing validation and lock order. |

## Payroll-package shared helpers

| Owner | Supported helpers | Verified consumers | Invariant to preserve |
|---|---|---|---|
| `app.payroll.eligibility` | `_period_has_driver_eligibility_snapshot`, `_is_snapshot_row_eligible_for_workdate`, `_assert_driver_eligible_for_workdate_via_snapshot`, `_assert_driver_eligible_for_period_via_snapshot`, `_create_period_driver_eligibility_rows`, `_regenerate_period_driver_eligibility_rows`, `_driver_has_existing_daily_source_on_date`, `_lifecycle_eligible_driver_ids` | Period creation/lifecycle, bonus, Day Grid, draft-line mutation, hub/off-driver/finalized-library reads, status sync; `test_cp2e_eligibility_snapshot.py` | A marker row distinguishes no snapshot from a deliberately empty frozen roster. Without a marker, work-date checks fall back to current lifecycle eligibility and preserve caller-selected existing-source rescue. With a marker, checks retain snapshot windows and current lifecycle eligibility. Rescue is exact-date; new draft lines disable it. `IncludedByExistingData` never grants new period-level Bonus authority. Draft-to-Open regeneration replaces provisional rows and freezes the snapshot. |
| `app.payroll.day_entry_state` | `_validate_status_key`, `_upsert_entry_state`, `_enforce_status_key_limits` | Day Grid; canonical-entry and status-limit tests | Canonical entry-state writes preserve field ownership (`set_status`/`set_note`); a status-only or note-only write leaves the other field untouched. Usage-limit checks exclude overwritten batch slots and add the batch's new contributions separately. |
| `app.payroll.status_payment_sync` | `_sync_status_payment_for_entry_state`, `_refresh_status_payment_lines`, `_resolve_live_status_payment_lines` | Day Grid, period lifecycle, period calculation; canonical-entry and calculation snapshot tests | The persisted `STATUS_PAYMENT` draft line is a compatibility projection. Read-time calculation resolves live pay from canonical nonvoid entry states and effective Approved/Superseded rates, without writes; an entry state whose status has no rate column is omitted. Keep the shared arithmetic and sync/resolver distinction. |
| `app.payroll.bonus` | `_load_active_bonus_events` | Live Calculation packet and report-evidence capture; `report_read_model` LIVE path | Selects only Active canonical `PayrollBonusEvents` for the period and company on the caller's existing connection; retains the driver/employee and creator display joins, ordered `(driverid, payrollbonuseventid)` rows, and raw mapping objects. It opens no transaction and does not authorize or project the rows. |
| `app.payroll.period_calculation` | `_build_live_calculation_packet` | Period lifecycle, current hub, report read model; `test_cp5a_current_hub.py` patches the existing qualified builder seam | Builds the authoritative live packet and blockers without persistence. `_LiveCalculationPacket` is defined here and imported by `calculation_snapshot` for snapshot-writer typing; other packet dataclasses remain local. |
| `app.payroll.calculation_snapshot` | `_capture_calculation_snapshot` | Period lifecycle submit/resubmit | Persists the packet and captured report evidence in the caller-owned transaction. It consumes the calculation packet without recalculating, rejects blockers, and excludes generated IDs from the hash. Lifecycle evidence gates remain in force. `_load_report_evidence` and `_packet_driver_totals_for_hash` are local writer helpers. |
| `app.payroll.report_read_model` | `_snapshot_evidence` | Report read model and finalized-library read model | Checks that the snapshot identifies the same company, branch, and period. Missing report-evidence version returns unavailable/empty collections; otherwise it reads captured status and bonus evidence without reconstructing mutable evidence. |
| `app.payroll.line_audit` | `_write_line_audit` | Bonus, Day Grid, draft-line mutation; batch-safety tests patch the existing `bonus` consumer binding | Keep audit writes in the caller's mutation transaction. |
| `app.payroll.mutation_lock` | `_lock_period_for_mutation` | Bonus, Day Grid, draft-line mutation; concurrency regression patches the existing draft-line consumer binding | Locks the period row `FOR UPDATE`, rechecks `SOURCE_ENTRY_STATUSES`, and raises HTTP 409 when the row is absent or no longer editable. The caller owns the transaction. This row lock is distinct from the branch workflow advisory lock. |
| `app.payroll.period_day_calendar` | `_validate_period_work_date` | Day Grid, draft-line mutation, off-driver operations | Always enforces period bounds. If frozen `PayrollPeriodDays` exist, rejects absent dates; legacy periods without day rows fall back to bounds only. Configured-off days remain metadata and are not rejected. |
| `app.payroll.immutable_evidence` | `_participant_snapshot` | `audit_evidence` | Captures the actor display name and permission/role evidence used by the audit-evidence writer. It is evidence collection, not an authorization decision. |
| `app.payroll.source_evidence` | `_capture_source_evidence` | `draft_line_mutation` | Adapts ordinary source-line mutations to audit evidence with stable period/pay/rate definition context and no fabricated legacy PayItem identity. |
| `app.payroll.source_line_read` | `_get_line_by_id` | `draft_line_mutation` | Shared company-scoped row lookup using the source-line projection; the module remains a read model without mutation locking or audit policy. |
| `app.payroll.period_creation` | `_check_slot_matrix` | `current_hub` | Checks duplicate active slots across Draft/Open/InReview/Returned, then applies the existing Open/Prepared creation-mode rules. Valid modes return `(creatable, error_code)`; an unknown mode raises the existing candidate error. |
| `app.payroll.guards` | `_require_non_driver_rate_subject`, `_check_driver_read_access` | Payroll Rates and Driver Pay Rules; acceptance-matrix tests patch the existing rates consumer binding | Rate and driver-pay-rule security checks stay within Payroll. `_check_driver_read_access` returns the authorized driver's branch for the caller's existing branch-scoped read. |

The current scan also verifies local-only examples: `_CalculationPacketLine` and `_CalculationPacketDriverTotal` are defined and consumed inside `period_calculation.py`; `_LiveCalculationPacket` is defined there and imported by `calculation_snapshot` as the shared packet shape. `_load_approved_snapshot_packet` is defined and consumed inside `finalization.py`. Test descriptions may name these helpers, but that alone does not make them cross-module production contracts. The shared contracts above do not remove lifecycle evidence gates or enable gated paths. This guide does not grant support status to other underscore-prefixed names.
